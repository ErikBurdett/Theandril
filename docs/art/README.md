# Using the art factory

From the repository root, use `pnpm art:doctor`, then `pnpm art:status`. Aseprite is discovered from the existing Steam installation; `ASEPRITE_BIN` overrides it. Pixel Snapper can be built with `bash tools/art/install-pixel-snapper.sh`; its binaries/build caches remain project-local and ignored.

## Source to runtime

1. A brief under assets/art/briefs names stable content bindings, native frame sources, palette, pivots/timing, constraints and original provenance. The four original sheets and revised revenant can be re-extracted with `pnpm art:prepare`; `pnpm art:overlays` prepares the eight original code-native overlays. Run overlays before prepare when rebuilding their combined index from nothing. Extraction never approves anything.
2. `pnpm art:generate unit.guard` runs source-backed processing through real Pixel Snapper and Aseprite. This default reuses commissioned sources; it does **not** claim to create a new AI image. `--provider pixellab|perfectpixel|comfyui` makes a new request only when explicitly selected and configured. The current CLI accepts one facing/idle clip; unsupported multi-state or invented animation is rejected.
3. `pnpm art:validate unit.guard` checks exact pixels/metadata and prints the candidate input hash. `pnpm art:review unit.guard` creates native/enlarged sheets. `--source` compares the pre-Snapper native image without granting approval.
4. Inspect actual pixels, role/identity, frame motion and palette. Approve one inspected candidate with `pnpm art:review unit.guard --approve --hash HASH --reviewer NAME --notes 'Observed findings and limitations' --evidence assets/art/review-previews/unit.guard-4x.png`. Approval is tied to that exact candidate; byte-identical frames, editable source, export metadata and evidence are retained outside the cache. Changed pixels/brief/tool/palette invalidate approval.
5. `pnpm art:atlas` rebuilds only reviewed approvals, checking reversed-input determinism. `pnpm art:integrate` publishes the approved atlas and catalogs to the web application. Publication does not claim the in-game visual review has passed.
6. Run `pnpm dev`, start a seeded game and open **Art Lab** in development. Inspect native sizes,1/2/4/8x, frame playback, exact atlas rectangles, backgrounds and repeated terrain. Playwright gameplay screenshots and performance/save checks are the final integration evidence.

`assets/art/source` and `assets/art/approved` are durable. Candidate pointers, temporary comparisons and tool/runtime processing caches are disposable and ignored; approved manifests must never require those caches. The production build retains approved runtime PNG/JSON only, omitting the Lab catalog and reserved candidate preview files.

## Biome variants and animation rollout

`pnpm art:biomes` validates the 24 independently generated originals in `assets/art/source/biome-variants/generation.json`; `--prepare --id=terrain.grassland.variant_1` writes immutable native pixels, processing records and an unapproved brief. Published/approved preparations cannot be overwritten. The original base plus two fixed slots are chosen deterministically from world seed and cell. `node --import tsx scripts/art-biome-review.ts --biome=grassland` creates original/variant1/variant2 native and enlarged mixed-repeat evidence; add `--approved` for durable reviewed sources. Neither command grants visual approval. Preserve rejected originals and exact provenance.

The [qualified Ashen scout revision 5](../../assets/art/approved/unit.scout.ashen_compact.json) is published with four 250 ms southeast idle frames; the other 431 qualified faction assets remain static. The generic guard/scout/caravan retain their older four-frame idle clips. This is not a complete faction animation set.

`pnpm art:animation:coverage` emits an exact published-atlas inventory of every non-terrain sprite, its clips, durations, distinct visible-pixel hashes, current consumers and explicitly future rollout requirements. Add `--summary` for counts. Different pixels are not proof of a good animation; terrain is excluded. `pnpm art:animation:prepare` dry-runs the measured four-pose Ashen scout import; `--prepare` writes immutable native frames/recipe/brief only and does not activate or approve them. One common scale and four measured foot anchors preserve actual source motion. Old static approvals remain recoverable. Native/playback/loop inspection, individual input-bound approval and in-game checks remain required. Locomotion/action hooks and other culture animations are not implied by this first idle pilot.

This is neither a finished directional/action animation set nor game 1.0 signoff. [Visual bible](THEANDRIL_ART_BIBLE.md) and [faction coverage](FACTION_ASSET_CATALOG.md) define actual consumers and remaining gaps. Without `--id`, preparation covers all 37 slice-12 assets, including two biomes and five improvements. It never generates, approves or publishes. ## Provider configuration

- PerfectPixel: `PERFECTPIXEL_BIN` must be upstream `ppvalidate`, not the GUI. A supported upstream provider key must be present. Current adapter deliberately exposes base-image mode only; it does not silently mirror asymmetric equipment or promise a seed it cannot set.
- PixelLab: `PIXELLAB_API_KEY`; the fixed official Pixflux-v2 endpoint supports still images and one optional init image in this adapter. Character/animation/hex APIs are not yet integrated.
- ComfyUI: local loopback `COMFYUI_URL`, and `COMFYUI_WORKFLOW` pointing to an API-format workflow with explicit prompt/seed/width/height bindings and model-license notes. No model download is hidden in generation.
- Built-in Codex generation: operated by the agent tool, with the original prompt/output copied into source provenance. A source-file bridge is available; the Node CLI cannot invoke that session-only tool itself.

Never commit provider secrets or infer commercial rights from an API response. Record unavailable model/seed information honestly. See GENERATOR_BAKEOFF.md and ART_IMPLEMENTATION_STATUS.md for verified versus untested capabilities.

## Checks and revision

Run `pnpm art:verify-tools` for real native import/export timing, tags and repeated byte equality; this requires the locally installed Aseprite and Pixel Snapper tools. Ordinary CI needs neither tool nor credentials: retained approved frames, editable sources, exact review evidence and catalogs are self-contained. `pnpm art:validate`, `pnpm test`, `pnpm bench:art` and gameplay tests validate those published artifacts. `pnpm art:doctor` also runs on a new checkout with missing art inputs and reports what needs configuration.

Reject a visually defective candidate with the same exact-hash/reviewer/notes/evidence arguments but `--reject` instead of `--approve`. Machine-valid is not visually approved: the first revenant passed pixel checks but was rejected for a detached tablet, then regenerated and individually reviewed as version 2. Rejected evidence remains under assets/art/rejected and never enters the runtime atlas. Changing a brief does not silently replace its last reviewed published version; process and inspect the revision before promoting it.

The current atlas compiler uses one bounded 1024/2048 page per explicit build. The preceding 134-asset pack overflowed 1024; the current 500-asset / 521-frame publication fits one 2048 page without shrinking native pixels. It contains 432 qualified culture assets and 68 shared assets, including 24 biome variants. `pnpm art:integrate --page-size 2048` preserves native pixels on a 16 MiB page, and 2048 is the CLI default. A deliberate `--page-size 1024` remains available and fails on overflow rather than shrinking or dropping assets. Automatic multi-page grouping is future scale work. DOM image decoding can separately allocate another 16 MiB. Pixel-perfect native previews use integer zoom, while gameplay currently fits these assets to its unchanged regular-hex geometry with explicitly reported fractional scaling.

The [published catalog](../../assets/art/runtime/catalog.json) records PNG SHA-256 `e32c73be1b8789f8c554eea7c6b7204d40fae20e3347be36ccbd76de8a9740de` (2,628,301 bytes). All 500 native approvals are published, and the main reviewer completed the [24-culture runtime galleries](FACTION_ASSET_CATALOG.md#current-in-game-review). The [pre-naval offline baseline](../performance/0025-art-before.json), [twelve-culture compiler report](../performance/0022-faction-art.md), [slice-16 renderer capture](../performance/0022-art-render-final.json) and [foundation report](../performance/0006-art-factory.md) remain historical measurements, not current 500-asset performance claims. Beyond the genuine Ashen scout idle pilot, directional/action animation, five researched-improvement pixel props and biome/shore transitions remain unfinished. Twenty-four published culture kits do not implement 24 supernatural rule systems or provide a complete 1.0 visual-production signoff. See [architecture](../architecture/0013-art-factory.md).

## Current integration evidence

The [500-asset offline run](../performance/0034-art-factions.json) retained seven warmed iterations, excluding filesystem reads: median validation **148.745 ms**, atlas packing **304.906 ms**, and PNG decoding **74.174 ms**. Peak process RSS was **609.570 MiB**; this is compiler-process memory, not a renderer or GPU budget.

The separate [isolated Huge browser run](../performance/0034-art-render.json) passed 1/1 with a synthetic fully explored 196,608-cell world, 32 factions, 1,500 global army containers and 32 towns, without advancing turns. Sampled frame p95 was **16.7–16.8 ms**; the atlas was **16 MiB**, and the largest retained cache reached **26 chunks / 104 MiB estimated power-of-two backing**, separately from the atlas and possible DOM decode. Packed cell transfer was **1,769,695 bytes**, within **1,973,677 total worker-transfer bytes**. The current state hash is `6effe876`: this schema-13/roster-4 campaign is **not byte-identical** to the older `cde1a697` capture despite retaining the authored physical placement and container workload. These viewport measurements do not establish late-game AI or total GPU memory performance.

All faction/24-roster, land/naval art, UI and character cases passed in the 500-asset browser checkpoint; the main reviewer inspected the [retained full-roster galleries](FACTION_ASSET_CATALOG.md#current-in-game-review), including [72 actual hull bindings and framing](../performance/0034-naval-art-inspection.json). The whole run was **109/111** before test-only corrections for a transient contact assertion after Pause and an obsolete full-hex selection expectation; the corrected follow-up passes **10/10**, and a later durable contact/land-gallery evidence run passes **4/4**. All 111 scenarios therefore have passing evidence across runs, not a single 111/111 invocation. The full headless checkpoint is **1,318/1,321**, with no skips: two AI-contact gates and the parallel Epic **62.280 s versus 60 s** gate remain open. The unchanged Short/Epic file separately passes **2/2** in isolation; production smoke passes **1/1**. [Implementation status](../IMPLEMENTATION_STATUS.md) and [art status](ART_IMPLEMENTATION_STATUS.md) retain exact results and release gaps.
