# Using the art factory

From the repository root, use `pnpm art:doctor`, then `pnpm art:status`. Aseprite is discovered from the existing Steam installation; `ASEPRITE_BIN` overrides it. Pixel Snapper can be built with `bash tools/art/install-pixel-snapper.sh`; its binaries/build caches remain project-local and ignored.

## Source to runtime

1. A brief under assets/art/briefs names stable content bindings, native frame sources, palette, pivots/timing, constraints and original provenance. The four original sheets and revised revenant can be re-extracted with `pnpm art:prepare`; `pnpm art:overlays` prepares the eight original code-native overlays. Run overlays before prepare when rebuilding their combined index from nothing. Extraction never approves anything.
2. `pnpm art:generate unit.guard` runs source-backed processing through real Pixel Snapper and Aseprite. This default reuses commissioned sources; it does **not** claim to create a new AI image. `--provider pixellab|perfectpixel|comfyui` makes a new request only when explicitly selected and configured. The current CLI accepts one facing/idle clip; unsupported multi-state or invented animation is rejected.
3. `pnpm art:validate unit.guard` checks exact pixels/metadata and prints the candidate input hash. `pnpm art:review unit.guard` creates native/enlarged sheets. `--source` compares the pre-Snapper native image without granting approval.
4. Inspect actual pixels, role/identity, frame motion and palette. Approve one inspected candidate with `pnpm art:review unit.guard --approve --hash HASH --reviewer NAME --notes 'Observed findings and limitations' --evidence assets/art/review-previews/unit.guard-4x.png`. Approval is tied to that exact candidate; byte-identical frames, editable source, export metadata and evidence are retained outside the cache. Changed pixels/brief/tool/palette invalidate approval.
5. `pnpm art:atlas` rebuilds only reviewed approvals, checking reversed-input determinism. `pnpm art:integrate` publishes the approved atlas and catalogs to the web application. Publication does not claim the in-game visual review has passed.
6. Run `pnpm dev`, start a seeded game and open **Art Lab** in development. Inspect native sizes,1/2/4/8x, frame playback, exact atlas rectangles, backgrounds and repeated terrain. Playwright gameplay screenshots and performance/save checks are the final integration evidence.

`assets/art/source` and `assets/art/approved` are durable. Candidate pointers, temporary comparisons and tool/runtime processing caches are disposable and ignored; approved manifests must never require those caches. The production build retains approved runtime PNG/JSON only, omitting the Lab catalog and reserved candidate preview files.

## Faction kit production

The twelve authored cultures each have 18 individually approved qualified roles: the historical 15-role land/UI kit plus three naval hulls, totaling 216 static southeast assets. This is not a finished directional/action animation set or twenty-four cultures. [Visual bible](THEANDRIL_ART_BIBLE.md) and [faction coverage](FACTION_ASSET_CATALOG.md) define actual consumers and remaining gaps. The first four land kits use retained sheets: exact source/revision prompts live in `assets/art/source/faction-generation-prompts.json` and `faction-revisions.json`. The dedicated `faction-index.json` never replaces the generic `foundation-index.json`; its historical sheet contract remains 15 roles.

Use `pnpm art:factions --propose-crops --family=ashen_compact` only when proposing a new source mapping. It writes unreviewed full-source/native/enlarged evidence; it does not grant approval. Inspect every role and add a review naming both the exact `sourceHash` and `cropsHash`. Keep any necessary component masks explicit. Do not repropose over an existing reviewed mapping merely to reprocess unchanged pixels. Opaque backgrounds, missing roles, omitted/duplicated source pixels and stale mappings fail.

`pnpm art:factions --family=ashen_compact` prepares native sources and briefs from that reviewed mapping; omit the family to prepare all four. Then `pnpm art:generate --family ashen_compact`, `pnpm art:validate --family ashen_compact` and `pnpm art:review --family ashen_compact` process and inspect the family. Final approval still names one asset and its exact validation hash, for example `unit.guard.ashen_compact`; there is no blanket family approval. `pnpm art:integrate` publishes only individually retained approvals. Keep static first-facing coverage separate from genuine animation production.

Iron Covenant and Sepulchral Synod use separate original generation calls per asset, not source sheets. Their current chosen sources, exact prompts and version paths are in `assets/art/source/slice12/generation.json`, with immutable per-source revision records. Run `node --import tsx scripts/art-slice12.ts` for dry-run source/margin inspection, or add `--prepare --id=unit.guard.iron_covenant` for explicit native/brief preparation. Without `--id`, preparation covers all 37 slice-12 assets, including two biomes and five improvements. It never generates, approves or publishes. Follow with the same individual generate/validate/review commands above. The old sheet command rejects these two cultures with routing guidance.

`node --import tsx scripts/art-slice12-review.ts --terrain-candidates` makes native/enlarged hex-repeat evidence before terrain approval. Without that flag, the script requires all 37 exact durable approvals and emits complete/per-family/land contact sheets plus repeat previews; it grants no approvals. The main-reviewed release evidence is retained in `docs/art/reviews/slice12-*`, not only in ignored temporary previews.

The next six cultures use independent per-role originals indexed under `assets/art/source/faction-expansion/<batch>/generation.json`: `miremorrow` currently contains Mire Courts only, `saltward` contains Saltwind/Wardhall, `rimesable` contains Rimehorn/Sable, and `morrow` contains Morrow Spore. These indexes name 90 selected originals from 95 actual calls; prompt plans or contact-sheet PNGs are not additional generations. Versioned sources/records/briefs and five rejected originals remain retained. [Root review decisions](../../assets/art/source/faction-expansion/root-review-decisions.json) record the processed 1×/4× acceptance; each final approval retains exact pixels, editable exports and durable evidence.

Use `node --import tsx scripts/art-faction-expansion.ts --batch=rimesable` for read-only preflight, or add `--prepare --id=unit.guard.rimehorn_clans` for native/brief preparation. This does not generate images or approve assets. Actual new originals come from the session-only built-in tool, one call per role, with source SHA-256, exact prompt, timestamp and honest unavailable model/seed metadata. Before approval, an explicit new source version can use `--activate-revision` after the pipeline verifies its retained prior evidence. Approved IDs are sealed against preparation changes; do not bypass that boundary to replace an approval. Then use `pnpm art:generate --family rimehorn_clans`, `pnpm art:validate --family rimehorn_clans` and `pnpm art:review --family rimehorn_clans` as above, followed by individual exact-hash review. There is no automatic family approval.

### Naval originals and review

All twelve cultures route their three naval roles through the dedicated [naval generation index](../../assets/art/source/faction-expansion/naval/generation.json), including cultures whose original land kit came from a sheet. The historical 15-role sheet layout and land-source routes are unchanged. Naval originals are independent per-asset calls, never crops from those sheets or recolored infantry. The batch retains 36 selected originals from 37 actual calls; [the rejected source record](../../assets/art/source/faction-expansion/naval/rejected-sources.json) preserves the first Synod ocean warship, whose mast touched the source edge. Its selected replacement is version 2.

Use `node --import tsx scripts/art-faction-expansion.ts --batch=naval --id=unit.transport.ashen_compact` for preflight and add `--prepare` only when creating a missing/new versioned input. Each native is 96×96, pivot `(48,80)`, one static `idle/se/0` frame at 250 ms with `loop:false`. Then process and inspect the individual ID with `pnpm art:generate unit.transport.ashen_compact` and `pnpm art:review unit.transport.ashen_compact`. Do not regenerate a previously reviewed land kit merely to add its hulls: a family-wide command now includes all 18 roles, and changed tool hashes must not rewrite retained preparation evidence.

`node --import tsx scripts/art-naval-review.ts --stage=candidate --cohort=1` validates exactly the first four cultures' processed candidates, writes a 1× overview and a 4× three-hull sheet per family, and records exact candidate/manifest/PNG/pixel hashes and sheet order. Cohorts 2 and 3 cover the remaining groups of four; `--family=ashen_compact` selects one family. `--cohort=all` requires all 36 selected-stage manifests. After individual approvals, `--stage=approved` reads only durable approvals and verifies their review hashes; it never substitutes candidates. These commands only produce review evidence: they cannot approve or publish. Within each family, sheet order is coastal warship, ocean warship, transport. See [individual naval approvals](FACTION_ASSET_CATALOG.md#naval-role-coverage) for the release boundary.

## Provider configuration

- PerfectPixel: `PERFECTPIXEL_BIN` must be upstream `ppvalidate`, not the GUI. A supported upstream provider key must be present. Current adapter deliberately exposes base-image mode only; it does not silently mirror asymmetric equipment or promise a seed it cannot set.
- PixelLab: `PIXELLAB_API_KEY`; the fixed official Pixflux-v2 endpoint supports still images and one optional init image in this adapter. Character/animation/hex APIs are not yet integrated.
- ComfyUI: local loopback `COMFYUI_URL`, and `COMFYUI_WORKFLOW` pointing to an API-format workflow with explicit prompt/seed/width/height bindings and model-license notes. No model download is hidden in generation.
- Built-in Codex generation: operated by the agent tool, with the original prompt/output copied into source provenance. A source-file bridge is available; the Node CLI cannot invoke that session-only tool itself.

Never commit provider secrets or infer commercial rights from an API response. Record unavailable model/seed information honestly. See GENERATOR_BAKEOFF.md and ART_IMPLEMENTATION_STATUS.md for verified versus untested capabilities.

## Checks and revision

Run `pnpm art:verify-tools` for real native import/export timing, tags and repeated byte equality; this requires the locally installed Aseprite and Pixel Snapper tools. Ordinary CI needs neither tool nor credentials: retained approved frames, editable sources, exact review evidence and catalogs are self-contained. `pnpm art:validate`, `pnpm test`, `pnpm bench:art` and gameplay tests validate those published artifacts. `pnpm art:doctor` also runs on a new checkout with missing art inputs and reports what needs configuration.

Reject a visually defective candidate with the same exact-hash/reviewer/notes/evidence arguments but `--reject` instead of `--approve`. Machine-valid is not visually approved: the first revenant passed pixel checks but was rejected for a detached tablet, then regenerated and individually reviewed as version 2. Rejected evidence remains under assets/art/rejected and never enters the runtime atlas. Changing a brief does not silently replace its last reviewed published version; process and inspect the revision before promoting it.

The current atlas compiler uses one bounded 1024/2048 page per explicit build. The preceding 134-asset pack overflowed 1024; the current 260-asset / 278-frame publication still fits one 2048 page without shrinking native pixels. It contains 216 qualified culture assets and 44 shared assets. `pnpm art:integrate --page-size 2048` preserves native pixels on a 16 MiB page, and 2048 is the CLI default. A deliberate `--page-size 1024` remains available and fails on overflow rather than shrinking or dropping assets. Automatic multi-page grouping is future scale work. DOM image decoding can separately allocate another 16 MiB. Pixel-perfect native previews use integer zoom, while gameplay currently fits these assets to its unchanged regular-hex geometry with explicitly reported fractional scaling.
