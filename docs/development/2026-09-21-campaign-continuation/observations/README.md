# Complete observation publication — 2026-09-21 continuation

This local M0 continuation reduces the cost of publishing the same observations.
It changes no rule, price, simulation state, visibility policy, query window,
planner activity, save schema or test budget. There is no new persistent cache.

## Why this work was selected

The retained
[`epic-integration-comparison.cpuprofile`](../../2026-09-21-roadmap-start/performance/epic-integration-comparison.cpuprofile)
shows **7.691 s** inclusive in `getObservation`, including **3.736 s** in
`getLandObservation`. Its explored-cell publication callback accounts for
**1.488 s** self time; detailed land-cell construction accounts for **1.027 s**
self, with another **0.778 s** self in the improvement-quote wrapper. These are
sampled overlapping stacks, not independent stage totals to sum.

The source repeatedly spread small temporary objects into every explored cell,
detailed land cell and improvement/cultivation quote. Those loops now construct
the same detached objects through explicit field assignments and known-field
copies. Rules version and remembered land/road references are read once per
publication. Optional property presence **and property insertion order** remain
the same. Quote functions, candidate enumeration, visibility checks and paging
logic are unchanged.

## Baseline and correctness evidence

Before production edits, [capture.ts](capture.ts) retained eight strictly imported
save inputs and **91 complete observation JSON strings** in [baseline.json](baseline.json).
The compressed payload has its own SHA-256; it is not regenerated by tests.
Original source copies are [simulation-before.ts.txt](simulation-before.ts.txt)
and [territory-before.ts.txt](territory-before.ts.txt).

The corpus includes generated grain/resource construction before payment, during
paid work and after completion; visible and remembered foreign hearths; a paid
road segment; embarked passengers; and seventeen explicitly authored towns on
generated terrain. It covers full details, omitted details, selected IDs,
rotating windows, maximum-safe offsets, disabled development candidates and
rules 10/15/17. Town-level direct reads have separate captured complete outputs.
The authored population/ownership setup is observation-volume evidence, not
earned-economy or mature-campaign proof.

[observation-publication-equivalence.test.ts](../../../../packages/sim/src/observation-publication-equivalence.test.ts)
compares every captured serialized byte at equivalent save/load boundaries,
including optional presence, field order, fog memory, prices and blockers. Caller
mutation checks cover cells, claims, worked arrays, yields, quotes and active work;
future reads and canonical saves remain unchanged. Real paid construction and
completion also compare complete immediate values and exact restored output.
Invalid owner/detail/cell windows still reject, and private-town lookup stays null.

The first focused run exposed a **test lifecycle mismatch**, retained in
[focused.txt](focused.txt): freshly emitted event properties precede save-schema
parsing in a different insertion order. It was not a runtime observation change.
The test now compares all immediate values and additionally compares every byte
after the same save/load boundary used by the captured input. None of the 91
captured output checks was relaxed or regenerated.

The final [focused run](focused-final.txt) passes **69/69 tests across five files**:
new publication equivalence, land queries, territory, territorial growth and AI
observation options. It includes the existing paid-command/save-mirror planning
checks. Parent verification owns whole-workspace typecheck/lint, full integration,
browser coverage and complete campaign timing.

## Paired measurements

Run from the repository root, in an exclusive CPU window:

```sh
/home/telephoneheater/.local/share/mise/installs/node/22.23.2/bin/node --import tsx docs/development/2026-09-21-campaign-continuation/observations/benchmark.ts
```

[benchmark.json](benchmark.json) was captured with Node 22.23.2 on an Intel Core
i9-13900K. [load-baseline.ts](load-baseline.ts) loads the retained original
observation implementations into a temporary module, preserving their original
territory dependency while sharing unchanged current dependencies. Working
source is never swapped. Both implementations read the same input. Every case
checks full JSON equality outside timing and retains output bytes/hash.

Four warmups precede twenty alternating paired samples. Timings include complete
observation construction, except the explicitly identified land-only case; setup,
save serialization, JSON equality and hashing are outside timing.

| Workload | Original median | Current median | Unchanged output |
| --- | ---: | ---: | ---: |
| Generated completed resource works | 0.404 ms | 0.260 ms | 186,871 bytes |
| Remembered foreign hearth | 0.286 ms | 0.206 ms | 185,744 bytes |
| Naval cargo observation | 0.732 ms | 0.325 ms | 312,097 bytes |
| 17 authored towns, full detail | 2.031 ms | 1.054 ms | 2,479,636 bytes |
| 17 authored towns, existing eight-town window | 1.030 ms | 0.598 ms | 1,211,470 bytes |
| 17 authored towns, existing summaries | 0.328 ms | 0.191 ms | 155,581 bytes |
| 17 authored towns, land observation only | 1.493 ms | 0.797 ms | 2,334,899 bytes |
| Synthetic fully charted Standard map | 39.471 ms | 10.425 ms | 8,161,003 bytes |

The Standard case has 98,304 charted cells and no towns; full exploration is
explicit authored knowledge over a generated world. It isolates publication
volume, not a mature Huge/Legendary realm or browser frame rate. The benchmark
also checks the original invalid-detail rejection messages against current code.
These microbenchmarks do not independently establish a full campaign speedup or
hosted timeout resolution.
