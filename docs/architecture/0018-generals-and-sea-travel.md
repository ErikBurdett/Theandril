# 0018 — general-led armies and sea travel

Date: 2026-09-05. Status: implemented and integrated; not a completed 1.0 military gate.

The user requested larger general-led armies with skill trees and ocean transport/naval warfare. Extend the existing formation containers, real characters and shared combat kernel rather than introducing a second military simulation.

New unled armies accept twelve formations. A healthy attached marshal commands sixteen; earned prerequisite-based command nodes can raise this to eighteen/twenty. Preserve existing exclusive specializations and add separate learned tree nodes. Leader loss preserves every formation, blocks additional troops and limits an over-command army to one movement until reorganized or competently led. All capacity/skill decisions originate in simulation. The tactical grid expands to five columns/four ranks for modern twenty-formation battles; historical rules remain twelve/three ranks.

Fleets use the same formation containers but cannot mix land troops and ships. A separate canonical transport relation binds each carried land army to one owned fleet. Every surviving transport formation carries eight land formations; no nested transport. Boarding consumes the passenger army's movement and one fleet movement. Landing requires a currently visible legal adjacent shore, spends one fleet movement and leaves passengers unable to move until refresh. Carried troops retain their identities and characters but cannot act or supply independent vision. Fleet movement and losses propagate to cargo deterministically; excess cargo is lost in stable descending army/formation-ID order, never silently overfilled or granted a free landing. Battle snapshots retain entering cargo provenance, and save validation checks actual losses against surviving hull capacity. Opponents do not receive private passenger snapshots, officers or aftermath. Manual naval combat and autoresolve use the existing deterministic combat kernel with actual ship statistics and water-valid retreats.

Static water depth is a compact land/shallow/deep array. Generator 3 adds coastal shelves without changing land, existing biomes, fertility or starts. Existing generator versions reproduce their geography and legacy projections omit newly derived metadata. Coastal navigation, harbor construction and real ship recruitment establish access; ocean navigation and suitable hulls jointly gate deep water. Movement previews, queued paths and AI must use these same rules.

Paused routes retain their original domain-valid geography even if a newly merged coastal hull removes deep-water capability. Loading that legitimate interruption must succeed; resuming explicitly replans against the fleet's current capability. This distinguishes a saved interrupted order from an executable route and prevents a legal reorganization from creating an unloadable save.

Save schema/rules 8 migrate schema 7 explicitly; genuine pre-change schema-7 mission, pending Rally battle and aftermath are retained in `packages/chronicle/src/fixtures/v7-archives.json` (gzip/base64, independently captured before content changes). Portable archive format stays version 2 with monotonically versioned records. Root owns canonical transport, save/record integration and verification; independent agents own general/character rules, geography/naval content, and human controls respectively.

Historical migration checks the frozen pre-naval unit, building, technology and specialization IDs before adding modern defaults. Recomputing a checksum cannot smuggle a new ship, harbor or skill into a schema-7 origin. Exclusive old battle leadership and twelve-formation kernels remain versioned independently of modern play.

UI integration exposes skill prerequisites, actual command capacity, repair options, water depth, fleet recruitment, cargo capacity and legal landings. Ship hulls are explicit procedural fallbacks; the existing 97 approved assets are unchanged, and twelve faction-specific hull variants remain unapproved future work. Closing an officer dialog must retain army selection and restore opener focus, including when assignment disables the previously focused control. Crowded-town assignment options are not silently truncated: a regression covers the hundredth co-located army.

Observation-only AI pays for navigation, harbors and varied hulls, assembles transport capacity, boards real troops, sails and lands before resuming land objectives. Bounded planning does not constitute persistent invasion logistics. Victory-project location now compares up to 64 eligible hosts and 64 observed threats, local garrison support and friendly settlement depth, with deterministic ties. Assessment runs only when the project is actionable; it never waits for an impossible guarantee of safety. Pacing changes and retained failed hypotheses are documented separately in [the diagnostic](../performance/0013-pacing-diagnostics.md).

Schema 8 raises only Epic's project commitment from 60,000 to 75,000 coin, retaining the 60 active response turns and identical early economy. The larger general-led economy shortened the archived duration gate; stronger host selection addresses a separate real AI weakness exposed by captured projects. These are not minimum-turn locks or hidden AI grants. Rules4–7 select an explicitly frozen price profile; contextual observations, affordability, spending and replay use the same versioned quote. Modern content is sealed as `257e1e91`.

Acceptance requires real commands, human and AI use, saved voyages/battles, historical replay, transport conservation/fog checks, narrow-screen inspection and measured larger battles/loaded fleets. This is not full 1.0 supply, invasions, naval diplomacy, officer politics or final ship animation.
