# Live UI and natural-play evidence

This is an audit, not a visual approval or a balance certification. All paths below are relative to this directory unless a repository path is explicitly given.

## Method and limits

- Baseline commit `b0a4cd86cdb30cd9e2d3a1f0c8a78da38f7987cd`; dedicated Vite audit server `http://127.0.0.1:5191/` (not the already-running user server).
- Campaign A: Ashen Compact, seed **20260909**, Small **256 × 160**, **12 realms**, Continents, Standard pace, lead-a-realm mode. Began in the actual setup screen and played to **turn 30** using UI actions. No state/treasury/research grants and no AI substitution for the player. The player chose a scout-led northern then eastern survey, workshop-first development, a second settlement, practical research, an institution and a Waykeeper.
- This is an expert auditor acting as an uninformed first-time player, not a recruited usability participant or a statistically representative strategy. The camera/debug API supplied read-only known movement coordinates, state hashes and observations. DOM button activation exercised the real React controls; map movements used actual CDP pointer events. Exact mouse ergonomics were not exhaustively timed.
- Initial turns 1–4 included ineffective map clicks because the browser helper did not send a full pointer sequence. Raw mouse-move/press/release fixed this at turn 5. Those idle turns are a **testing-tool artifact, not an AI or game-input finding**. The action log explicitly marks the correction. Several browser capture/input timeouts and a later tool-tab reset to `about:blank` were likewise not counted as game crashes. The resource fixture was reimported into a recovered tab and completed.
- Browser views inspected at 1440×1000 and 390×844, including 130% text scale. Narrow checks showed document width 390 at viewport width 390; research dialog width and scroll width both 368. These are positive no-horizontal-overflow observations, not full accessibility/mobile certification.
- `actions.jsonl` is the append-only action record. Each numbered screenshot has accompanying `.txt` rendered text and `.json` summary/hash/selection/performance/viewport evidence. `theandril-turn-30.theandril` is the exported natural campaign. Dev-only Art Lab/debug hooks must not be confused with production features.
- `make-fixtures.ts` exports existing test-fixture states through the actual persistence codec. Controlled border combat and grain extraction below are **not natural Campaign A**. `fixture-saves/manifest.json` records identities and hashes. No production source was modified.

## Controlled battle and economic probes

### Border battle — existing authored fixture, turn 1

Imported `border.theandril`. Declared war on Reedbound Council through Realm affairs. Inspected the peace panel: coin offered/requested, duration, review and send; review correctly warned that the conflict was too recent for white peace and that a longer binding peace helped acceptance. Did not send this offer before combat.

Opened the Ashen Vanguard's actual attack control. The resulting battle at **hex 537** contained two Oath guard formations, **120 soldiers** total. Chose **Brace**, observed round 1 and automatic Set shields, inspected the 4× detail camera, then used auto-resolve. The report recorded **8 rounds**, Ashen Compact held the field, **25 losses / 35 survivors**, Reedbound **33 losses / 27 survivors**, enemy retreat to **538**. The main map returned with a short bottom status message; the substantial report required opening the Campaign journal. Sources: `36-controlled-diplomacy` through `42-battle-aftermath`, `46-earned-training`; `fixture-saves/border.theandril`.

Then opened Research → Development → Formation training → Ashen Vanguard → Field habits. Paid **3 earned battle experience + 8 coin**; treasury changed **60 → 52** while survivors stayed **35**. The training system genuinely preserves casualties rather than healing for free. A positive connected loop: battle → survivors → experience → permanent company training.

### Grain extraction — existing deposit fixture, turns 5–9

Imported `grain.theandril` from `grainResourceCampaign` (generated seed 17, Epic pace, one faction, starting forces relocated by the existing fixture; founding and market construction paid by that fixture). In the actual town panel selected **hex 302**, assigned a worker, built **Hearthgrain grange**, then advanced four turns. Resource tab reported **3 stored grain, +3/turn**. Sold one using the actual market control: grain **3 → 2**, treasury **71 → 73**. Sources: `47-grain-land`, `48-grain-extraction`, `49-grain-market-sale`, action log; `packages/test-fixtures/src/resource-fixture.ts:10-29`.

The extraction chain is real: geography → ownership → works → worker → stockpile → market. Do not report resources as cosmetic or disconnected. What remains a design question is the breadth of material uses, market counterplay and automation, assessed separately against implementation and long campaigns.

## Positive usability and engineering observations

- Map-first buttons, full orders, search, force-type filter, stable/name sort, shortcuts, previous/next controls and dialog close controls exist. A blanket 'add hotkeys/search' recommendation would be wrong.
- Many actions quote live costs and precise blockers. Non-coastal harbor rejection, arcane aptitude checks and occupied character-assignment checks were understandable once found.
- Queueing more than one building/unit works. Army recruitment produces separate detachments and says so explicitly. Real merging/command capacity should be evaluated against this deliberate model, not mistaken for missing armies.
- Institutions and doctrines explicitly warn that the other choice becomes permanently excluded.
- Save/load and compressed export worked in the natural campaign with canonical hash equality.
- Narrow layouts wrap rather than horizontally overflow in the checked views. The issue is density and discovery, not a demonstrated unusable mobile layout.
- Pixel terrain, restrained dark wood/bronze UI, serif display text and in-world ledger language give the project a coherent direction worth preserving. Sprite/portrait completion and runtime role readability still need the separate art audit.
